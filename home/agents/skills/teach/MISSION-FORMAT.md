# Establishing the learning goal

Keep one mission in `MISSION.md` at the workspace root. It guides topic selection, resources, and exercises across sessions. Two unrelated goals need separate workspaces.

Ask what the user wants to do with the skill when the answer is missing. “Learn Rust” does not yet distinguish language study from shipping a CLI to a team; “run a half marathon by October” gives more direction than “get fitter.” Use the concrete outcome rather than filling gaps with a goal of your own.

Capture the answer in this shape:

```md
# Mission: {Topic}

## Why
{The real-world goal and what changes when the user can do it.}

## Success looks like
- {An observable ability}
- {Another observable ability, when needed}

## Constraints
- {Time, budget, commitments, or learning preferences that affect the approach}

## Out of scope
- {Adjacent topics the user explicitly chose not to pursue}
```

Keep it to about a screen. The mission is a compass, not a lesson plan. When the user confirms a changed goal, revise this file and write a learning record explaining the shift so later sessions use the current direction.
